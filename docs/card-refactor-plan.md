# Card refactor plan: one accessible event card

**Status**: plan only, no code in this PR. Delete this file when the implementation ships (see `docs/README.md`).
**Scope**: `CardLayout` (events, news), the home carousel card, skeletons, the ad card. One PR into `develop`, three commits so each can be reviewed and reverted alone.

This plan was reviewed by two independent AI reviewers (accessibility/CSS, repo rules/risk) before opening this PR. Their findings are folded in below; "Changes after review" lists what they changed.

## Why

- A screen reader reads each title twice (link `aria-label` plus a hidden copy, then the `<h3>`), and a third time through the image `alt`.
- The card link is `absolute inset-0` inside an `overflow-hidden` article, and `.pressable-card` has no focus style, so the keyboard focus ring is clipped (WCAG 2.4.7). Confirmed with a static copy of the card markup: on focus, 0 pixels change in Chromium 156, only a thin sliver on one edge shows in WebKit 27.2, and part of the ring shows in Firefox 157.
- `CardHorizontalServer` copies `CardLayout`'s markup with smaller text; `CardLayout` takes ~25 props (rule: 10 or fewer).
- `DESIGN.md` describes a hover shadow and a grid that the code does not have.
- `· Diversos dies` repeats what the date range already says.

## Commit 1: refactor, no visible change

1. Add a `CardData` type (`types/props.ts`). `prepareCardContentData` returns it for events; `NewsCard` builds one by hand (it does not use `prepareCardContentData`). `CardLayout` takes `card`, `layout`, `compact`, `href`, `analyticsEventName`, `description`, `position`, `isPriority`, `renderLink`: 9 props, 10 with `headingLevel` from commit 2 (the limit; don't add more).
2. Remove dead fields from `prepareCardContentData`: `viewCountAriaLabel`, `timeLabels`, `isMultiDay`, `categorySlug`, and the `tTime` parameter (plus `CompactCardProps.tTime` and its callers). Then delete the `CardContent.viewCountAria` key (ca, es, en) and drop `EventTime` from `CLIENT_UTILS_KEYS` (`lib/i18n/client-namespaces.ts`): `CardContentClient` is its only client user (`EventCalendar` reads it on the server), and `test/i18n-client-namespaces.test.ts` warns about unused entries.
3. Merge `CardHorizontalServer` into `CardLayout` through `compact` (`px-3.5 pt-2.5 pb-3.5`, `text-sm` title with no min height, `text-xs` meta line that keeps `truncate`, `w-3.5` pin icon, image context `list`). The two cards pass a different `imageContext` (`location`/`region` fallbacks); only the placeholder receives it and `ImgDefaultCore` reads just `title`, so this is not a visible change. Delete `cardHorizontal/CardHorizontalServer.tsx`, `cardHorizontal/index.tsx` (imported nowhere) and the `CardHorizontal*` types. `EventsAroundServer` renders `CardContentServer compact`.
4. Locale: `EventsAroundServer` already holds `rootLocale()`. `CardContentServer` gets an optional `locale` prop and falls back to `getLocaleSafely()` (reads `headers()`) only when it is missing, so the carousel does not start reading `headers()`.

6. `EventCardSkeleton`: hairline border like the card instead of a shadow. Same for the carousel loading card (`EventCardLoading` in `EventsAroundServer`, `shadow-sm`). Client skeleton grid in `HybridEventsListClient`: `gap-element-gap` (12px) to `gap-5` (the real list).
7. Test that the compact card's markup and classes are unchanged.

## Commit 2: accessible link pattern

1. **Title is the link.** `<h2|h3><a class="card-event-link">title</a></h2|h3>`. `.card-event-link::after` is `position:absolute; inset:0; z-index:1` and stretches over the article (`relative`). The link must not be positioned or transformed. Remove `aria-label` and the `sr-only` copy. The card link uses variant `plain`: `pressable-card` applies a `transform` on `:active` that would shrink the `::after`. `data-analytics-*` and `data-pressable-link` stay on the link. The `position` number of numbered rows (`NewsEventsSection`, inside an `<ol>`) stays in the heading but outside the link, `aria-hidden`, so the link name is just the title; the `<ol>` already gives the order.
2. **Heading level.** `headingLevel` (`h3` default), passed through `Card`, `CardServer`, `EventsSection` and `NewsCardGrid` (#686). `h2` only where cards sit directly under the page `<h1>`: `HybridEventsList`, `ClientCardsList`, the main `NewsList`, `/preferits` (the guest list in `page.tsx`, and `EventsSection` for the signed-in and `passats` lists) and `/perfil/[username]` and `passats` (`EventsSection`; those lists have only a `<section aria-label>`, no `<h2>`). Cards under a section `<h2>` keep `h3`: related and latest news, the news-article event rows, the profile "upcoming in town" fallback (`ProfileEventsSection.tsx:65`), home carousels.
3. **DOM order.** Title first inside the body div, flex `order-*` keeps badges and date above it visually. The body stays after the image div, so the LCP image is still first in the HTML. Tab order changes: the favorite button now comes before the title link.
4. **Decorative image.** Card images get `alt=""`. `alt === ""` makes the image decorative in all four places that label it today: `ImageServer` fallback, `ClientImage` no-sources and error fallbacks (`role="img" aria-label=...`, hard-coded Catalan "Imatge no disponible") and `ImgDefaultCore` (`role="img"` when it has a title). Only callers that pass `alt=""` are affected, so the event page, profiles and sponsors keep their labels.
5. **Focus ring** on `.card-event-link:focus-visible::after`: `outline: 2px solid` primary, `outline-offset: -2px`, explicit 12px radius (the article clips square corners), plus a 4px inset white band so the ring keeps 3:1 over any photo. The link itself gets `outline: none`. The navbar is sticky at the top from the `nav:` breakpoint (950px), and below it a fixed bottom bar covers the last `--mobile-nav-clearance` of the viewport (`NavbarClient.tsx:188`). Scroll margins apply to the focused link (the title), not the card, so they add the part of the card on that side of the title: `scroll-margin-bottom` is the part of the card below the title plus `var(--mobile-nav-clearance)` below `nav:`: 4.5rem on the default and compact layouts (the rest of the 2-line title min height, the location line and padding: ~66px measured; 3rem left the first row 18px under the bar), and 9rem on `featured` and `row` (~143px at most), which also render up to three lines of description and a `mb-3` between the title and the location (`CardLayout.tsx:106-112`), so the allowance is set per layout (a modifier class on the article), not once; measure both in `verify-que-fer`; `scroll-margin-top` is the navbar height from `nav:`; plus `scroll-margin-inline`. Tabbing down then shows the whole card above the bottom bar. The image above the title grows with the card width, so on Shift+Tab or a card taller than the viewport only the title is guaranteed visible, which meets WCAG 2.4.11 (the focused link is never fully hidden). Check the article bounds after keyboard scrolling in `verify-que-fer`.
6. **Hover and press.** Hover rules (border, image zoom 1.03) go inside `@media (hover: hover)`. The title colour on hover is dropped: `group-hover:text-primary/85` never generated CSS (85 is not in Tailwind's opacity scale), so it never shipped and `DESIGN.md` does not ask for it. Press feedback is `.card-event:has(.card-event-link:active)` with `transform: translateY(1px) scale(0.995)`, the same transform `.pressable-card:active` has today, so tapping the heart does not press the card (Safari older than 15.4 loses press feedback only). The global reduced-motion rule (`globals.css:551`) only zeroes durations; it does not remove transforms. So, like `.pressable-card` today (`globals.css:424-441`), the press transform and the image zoom both sit inside `@media (prefers-reduced-motion: no-preference)`; reduced-motion users get neither. The `shadow-card-hover` that `.pressable-card:active` adds is dropped on purpose: cards are border-only (`DESIGN.md` is being corrected to say so). `data-pressed` is only set by `PressableLink`, which cards do not use, so `:active` is the only press state they have today.
7. **`<time dateTime>`** for single-day events only (`<time>` cannot hold a range). Computed inline in `prepareCardContentData`: `test/prepareCardContentData.test.ts` mocks `@utils/date-helpers` with four exports, so a new helper would be `undefined` there.
8. Remove `pointer-events-none` from the body. This is required, not cleanup: `pointer-events` is inherited, so with the link inside the body the `::after` would get `none` too and clicks would land on the image (checked in all three engines: the hit test returns `IMG`, not the link). Also remove the double `z-10`/`z-[2]` on the favorite wrapper.

## Commit 3: copy and visual

1. **Multi-day dates.** `formatCardDate` also returns `endLabel` and `endDay`. A running event shows `Fins al 30 nov.`; one starting today shows `Avui · Fins al 12 nov.` and one starting tomorrow `Demà · Fins al 12 nov.` (the existing urgency label, so the start day stays right); later ones keep the range. `· Diversos dies` goes (`multipleDates` deleted from ca, es, en: `i18n:check` does not flag unused keys). New key `CardContent.until`, with Catalan elision for days 1 and 11 (`Fins a l'1`, `Fins a l'11`) through an ICU `select` on `day`. es and en use the same `select` with the same `1`, `11` and `other` branches, all with the same text: `{day, select, 1 {Hasta el {date}} 11 {Hasta el {date}} other {Hasta el {date}}}` and `{day, select, 1 {Until {date}} 11 {Until {date}} other {Until {date}}}`. `i18n:check` (`invalidKeys`) rejects a `select` in ca against a plain argument in es/en (`Expected element of type "select" but received "argument"`) and also a `select` whose option keys differ from ca's (an `other`-only `select` gives `Error in select`; `findInvalidTranslations` compares the option lists of two `select` elements, plural options loosely). Both reproduced, and the three-branch version passes. In the message, write the apostrophe before a placeholder as `''` (ICU escape): `{day, select, 1 {Fins a l''{date}} 11 {Fins a l''{date}} other {Fins al {date}}}`. A single `'` before `{` starts an ICU quote; with `icu-minify` (our precompiler) `l'{date}` renders `Fins a l{date}} 11 {Fins a l1 des.`. Add a unit test for days 1, 11 and 30. When the until label is shown the start time is hidden, because `Fins al 30 nov. · 18:00` reads as an end time.
2. Category badge `text-[11px]` to `text-xs`.
3. Ad card: reuse `Components.EventPage.sponsored` (client-listed) instead of hard-coded Catalan, `<p>` instead of `<h3>`, drop `cursor-pointer`.
4. Docs:
   - `DESIGN.md`: hover shadow (lines 281-283, 696-697, 826-827, 854-855) and grid text (676-678: it says 12px gap and 2 columns at sm, 3 at md; the code is `gap-5`, 2 at md, 3 at xl).
   - `docs/design-rationale.md`: §2.1 line 46 (`CardHorizontalServer`); in §2.2 "2-column grid" (the code has 3 columns at `xl`), "Contained cards (border + shadow …)" (cards are border-only), "Category badge on image (frosted glass)" (the badge is in the body) and "View counter behavior" (cards show no view count); §2.3 "All 3 card variants" (two after this change).
   - `design-system-conventions` skill: `.card-event*` classes.
   - `LESSONS.md`: "Avui/Demà" is computed at render and Cloudflare caches HTML for 30 minutes, so just after midnight a card can say "Demà" for an event now today.

## Changes after review

- Corrected: `CardLayout.tsx` is 123 lines, not 348, so no `CardMeta` split.
- `CardData` is a shared type, not just the return of `prepareCardContentData` (news builds its own).
- Heading level: `h3` default and only listings opt in to `h2` (a blanket `h2` for news breaks related-news, profile and home sections).
- Image decorative handling covers the error and placeholder paths, not only `alt`.
- Focus ring: explicit radius, contrast band, scroll margins; press feedback scoped with `:has()`.
- Carousel locale comes from `rootLocale()`, not `getLocaleSafely()`.
- Catalan elision and the hidden start time added. Reduced motion: the global rule only zeroes durations, so press and zoom stay inside `no-preference` (a second review round corrected my first "no separate rule" claim).
- Third review (every claim rechecked against `develop`, CSS tested in three engines): ICU `''` escape for the elision; `pointer-events-none` removal is required; `h2` also on `/preferits` and profile lists; bottom scroll margin for the mobile bar; `truncate` kept on the compact meta line; `viewCountAria` and the client `EventTime` namespace removed; more stale `design-rationale.md` sections; `position` number outside the link; the focus clipping is confirmed, not "probably".
- Fourth review (CodeRabbit, on the third version): the `until` message needs the same `select` structure in ca, es and en. Tested with `i18n-check`: a plain argument fails, a `select` with only `other` fails, three identical branches pass. Scroll margins on the link do not cover the card-sized ring, so the bottom margin gets an allowance and verification checks the article bounds.
- Implementation: the scroll allowances above were measured with Playwright on a production build (Tab keeps 7/7 cards fully visible at 375, 768 and 1280px). #686 moved the news grids into `NewsCardGrid`; only `NewsList` passes it `h2`.
- **Deferred**: `CompactCard` (already one named link, and it renders inside the `"use cache"` `EventPageBody`, so it needs its own change with `locale` kept as a prop); the ad placeholder height (the real height is unmeasured; `contain-intrinsic-size` is only an off-screen hint); favorite button focus ring in forced-colors mode; the rest of the unused view-transition code (`EventImage.tsx:49` and the `::view-transition-*(root)` rules in `globals.css`, nothing starts a transition).

- Not affected: e2e (nothing keys on the card `aria-label`, `alt`, `<h3>` or `pressable-card`; `favorites.flow.spec.ts` finds the heart through the nearest ancestor `div` that holds it, which is still the list item; `ads-hybrid-rendering.spec.ts` matches `Contingut patrocinat`, the same text in `ca`), analytics (`closest("[data-analytics-event-name]")` and `[data-pressable-link]` still match, and a click on `::after` targets the `<a>`), JSON-LD, service worker.
