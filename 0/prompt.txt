**1. Mobile users can't log out until they finish onboarding — confidence 88**

`/Users/albertolive/Repos/que-fer/components/ui/common/navbar/NavbarClient.tsx:44-49` and `:108`

Logout now exists in exactly two places: the desktop dropdown (`NavbarClient.tsx:206`, inside a `hidden md:flex` container) and `ProfileOwnerActions`. `ProfileOwnerActions` is rendered from exactly one place — `ProfileHeader.tsx:81`, mounted in `app/[locale]/perfil/[username]/layout.tsx:28`. Nothing renders it under `/perfil/edita` (grep for `logout` across `app/` and `components/` returns no other call site).

When `user.profileCompleted === false`, `profileHref` is `/perfil/edita` by design (line 45). So the mobile avatar sends the user to the edit form, which has no logout button. That's the state every newly-signed-up user occupies until they complete onboarding, and on mobile there is now no way out of the session at all.

Fix: render a logout affordance on the edit-profile page too, or keep one auth escape hatch in the mobile header for the `profileCompleted === false` case.

**2. `profileHref || "/"` silently sends "El meu perfil" to the homepage — confidence 85**

`NavbarClient.tsx:108`

`profileHref` is `null` when `getProfileSlug()` returns `""` (username is an email/UUID and no usable display name — see `utils/user-helpers.ts:19-70`). The mobile branch swallows that with `|| "/"`, producing a link labeled `aria-label={labels.myProfile}` that navigates home. Desktop handles the same state correctly by hiding the link entirely (`NavbarClient.tsx:198`: `profileHref &amp;&amp; !user.profileEnrichmentFailed &amp;&amp; ...`).

Fix: mirror the desktop guard — render the avatar as a non-link element (or fall through to the login/re-auth branch) when `profileHref` is null, instead of pointing it at `/`.

**3. The mobile "incomplete session" warning is gone, reversing a deliberate earlier decision — confidence 82**

`NavbarClient.tsx:105-135` (removed block visible in the diff)

The deleted mobile panel carried an explicit comment: *"Surface 'incomplete session' inside the mobile panel too, so the warning is visible without opening the desktop dropdown."* This PR removes `data-testid="navbar-session-warning-mobile"` with no replacement. The desktop equivalent survives at `:188-197`, so the behavior is now desktop-only again — the exact state that comment was written to prevent.

The new fallback itself is intentional and tested (`test/navbar-profile-link.test.tsx:126` — "falls back to the re-auth link on mobile when the session is only partially enriched"), and re-entering `/iniciar-sessio` is a plausible recovery path. The problem is that a logged-in user sees a control labeled `aria-label={labels.login}` ("Inicia sessió") with zero explanation of why their avatar disappeared. Screen-reader users get an outright false statement about their session state.

Fix: either keep a compact `incompleteProfile` indicator in the mobile header, or add a distinct label for the re-auth case rather than reusing `labels.login`.
